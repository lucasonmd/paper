# 프로그램 등록 신청서 정리

## 프로그램 명칭

**참조 관계 기반 토픽 자동 집계 엔진**

## 적용 분야

방위산업 차량 플랫폼 소프트웨어 — GVA(Generic Vehicle Architecture) 계열(NGVA/STANAG 4754, UK GVA, AS GVA) 데이터 모델을 사용하는 임무장비-플랫폼 통합 시스템의 DDS(Data Distribution Service) 발행-구독 미들웨어 응용 소프트웨어

## 본 프로그램의 특징

GVA 계열 데이터 모델에서 하나의 논리적 개체(장비, 부품 등)는 여러 개의 토픽(Topic)으로 나뉘어 개별적으로 발행되며, 각 토픽은 다른 토픽의 식별자(sourceID)를 속성으로 보유함으로써 서로 참조 관계를 형성한다. 종래에는 이러한 구조를 처리하기 위해 토픽 종류마다 별도의 수신 콜백 함수를 작성하고, 그 안에 저장·매칭·완결성 판단 로직을 각각 구현해야 했다. 이 방식은 토픽 종류가 늘어날수록 유사한 코드가 반복적으로 증가하고, 데이터 모델(참조 관계, 다중성)이 변경될 때마다 관련된 모든 콜백을 찾아 수정해야 하는 유지보수 부담을 가진다.

본 프로그램은 이러한 반복 구현을 제거하기 위해, 토픽의 종류(Kind)와 토픽 간 참조 관계(Relation) 및 그 다중성(One, ZeroOrOne, OneOrMany, ZeroOrMany)을 선언적으로 등록하는 방식을 채택하였다. 개발자는 각 토픽 종류마다 개별 처리 로직을 작성하는 대신, 어떤 토픽이 어떤 토픽을 어떤 관계로 참조하는지만 선언하면 되며, 저장·매칭·완결성 판단이라는 공통 알고리즘은 엔진 내부에 단 한 번만 구현되어 모든 토픽 종류에 재사용된다. 이로써 신규 토픽 종류를 데이터 모델에 추가할 때 발생하는 코드 수정 범위가 엔진 전반이 아닌 관계 등록부 한 곳으로 국한되며, 참조 관계나 다중성이 변경되어도 해당 선언만 갱신하면 되어 변경 영향 범위가 명확해진다는 것이 본 프로그램의 핵심 특징이다.

또한 본 프로그램은 토픽 간 참조가 양방향으로 선언된 경우, 완결성 판정 시 양쪽 토픽이 실제로 서로를 참조하고 있는지 상호 검증함으로써 한쪽만 갱신된 비대칭 상태를 걸러내는 기능을 제공하며, 다중 스레드 환경에서의 동시 수신을 지원하기 위해 저장소와 인덱스를 동시성 자료구조로 구현하고 루트 단위의 게이트 락을 통해 중복 통지를 방지한다.

## 주요 기능

1. **Kind 등록 기능**: CLR 타입과 식별자(키) 추출 함수를 하나의 쌍으로 등록하여, 임의의 토픽 클래스를 엔진이 인식하는 종류(Kind)로 편입시키는 기능
2. **관계 등록 기능**: 두 Kind 사이의 단방향(RegisterUnidirectional) 또는 양방향(RegisterBidirectional) 참조 관계를, 참조 대상 키를 추출하는 함수 및 다중성(One/ZeroOrOne/OneOrMany/ZeroOrMany)과 함께 등록하는 기능
3. **관계 인덱스 자동 유지 기능**: 각 관계에 대해 정방향(Forward)·역방향(Reverse) 인덱스를 자동으로 구성하고, 토픽이 갱신될 때마다 이전 참조 집합과 신규 참조 집합의 차이만을 반영하여 인덱스 일관성을 유지하는 기능
4. **영향 범위 자동 탐색 기능**: 토픽이 수신되면 관계 그래프를 정방향·역방향으로 탐색하여, 해당 토픽의 갱신으로 영향을 받는 루트 토픽(집계의 기준이 되는 최상위 토픽) 집합을 자동으로 식별하는 기능
5. **다중성 기반 완결성 판정 기능**: 각 루트에 대해 관계 그래프를 재탐색하며 선언된 다중성 요구조건(필수 여부, 개수 제약)을 검사하여, 집계가 완결되었는지를 자동으로 판정하는 기능
6. **양방향 참조 상호 검증 기능**: 양방향으로 등록된 관계에 대해, 완결성 판정 시 양쪽 토픽이 실제로 서로를 참조하는지 검증하여 한쪽만 갱신된 비정상 상태를 걸러내는 기능
7. **집계 스냅샷 구성 및 통지 기능**: 완결로 판정된 루트에 대해 관련 토픽을 모두 수집한 스냅샷(AggregateSnapshot)을 구성하고, 전역 이벤트 및 루트 종류별 구독 핸들러를 통해 구독자에게 통지하는 기능
8. **선택적 통지 정밀화 기능**: 다수의 루트가 하나의 하위 토픽을 공유하는 상황에서 발생하는 통지 확산을 제어하기 위한 옵션(EmitOnlyAffectedRoots-실제 갱신된 루트만 통지, SuppressUnchangedSnapshots-내용이 동일한 재통지 억제, IsolateAggregateBoundaries-양방향 관계의 역방향 탐색 생략) 기능
9. **동시성 제어 기능**: 다중 스레드에서의 동시 토픽 수신을 지원하는 동시성 자료구조 기반 저장소·인덱스 및 루트 단위 게이트 락을 통한 중복 통지 방지 기능
10. **JSON 기반 모듈 정의 로딩 기능**: Kind와 관계 등록 내용을 JSON 파일로 선언하고, 이를 읽어 리플렉션 기반으로 위 1~2번과 동일한 등록을 자동 수행하는 기능(JsonModuleLoader)

## 사용 방법

본 프로그램의 사용은 다음 세 단계로 이루어진다.

**1단계 — 토픽 종류와 관계 등록**
사용할 토픽 클래스마다 `AggregationEngine.RegisterKind()`를 호출하여 Kind로 등록하고, 토픽 간 참조 관계마다 `RegisterUnidirectional()` 또는 `RegisterBidirectional()`을 호출하여 관계와 다중성을 등록한다. 이 등록은 코드로 직접 작성하거나, JSON 모듈 정의 파일을 작성한 뒤 `JsonModuleLoader.LoadFile()`을 호출하여 일괄 등록할 수도 있다. 집계의 기준이 되는 토픽 종류는 `RegisterRootKind()`로 별도 지정한다.

**2단계 — 토픽 수신 연결**
DDS 등 발행-구독 미들웨어로부터 토픽을 수신하는 지점(리더의 수신 콜백)에서, 수신한 토픽 인스턴스를 그대로 `AggregationEngine.Upsert(kind, 토픽인스턴스)`에 전달하도록 연결한다. 토픽 종류가 몇 개이든 이 호출 형태는 동일하며, 저장·매칭·완결성 판단은 엔진 내부에서 자동으로 처리되므로 콜백 내부에 별도의 로직을 작성할 필요가 없다.

**3단계 — 완결된 집계 구독**
`AggregationEngine.SubscribeRootKind(rootKind, 핸들러함수)`를 호출하여, 해당 루트 종류의 집계가 완결될 때마다 호출될 핸들러를 등록한다. 핸들러는 완결된 집계 스냅샷(AggregateSnapshot)을 인자로 전달받으며, `TryGetOne<T>()` 또는 `TryGetMany<T>()`를 통해 집계에 포함된 개별 토픽에 접근하여 후속 처리(응용 로직)를 수행한다.

이 세 단계로 연결이 완료되면, 이후 토픽 종류가 추가되거나 참조 관계가 변경되더라도 1단계의 등록 내용만 수정하면 되며 2단계와 3단계의 연결 코드는 변경할 필요가 없다.
